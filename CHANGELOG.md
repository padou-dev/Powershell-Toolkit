# Changelog

## [1.3.0] — 2026-07-31

### Added
- `hash_ls`: interactive VirusTotal integration — select any listed file to see how many engines flag its hash (color-coded), with option to open the full report in the browser. Only the hash is sent, never the file. API key is read from the `VT_API_KEY` user environment variable (offered to save on first run); without a key, browser lookup still works. Handles 404 (hash unknown to VT), 429 (free-tier rate limit), and 401 (bad key) explicitly.

## [1.2.0] — 2026-07-23

### Changed
- **Installer no longer requires administrator rights** — everything installs in user scope (`Install-Module -Scope CurrentUser`, profile, `LOCALAPPDATA`)
- Profile is now managed via a marked block (`# >>> powershell-toolkit start >>>` … `# <<< powershell-toolkit end <<<`) instead of being overwritten; existing profile content is preserved and backed up with a timestamp before every change
- Install paths are derived from `$PROFILE` instead of `$HOME\Documents`, fixing installs on machines with OneDrive folder redirection
- Function registry moved out of `Setup.ps1` into `manifest.json` — adding a function no longer requires editing the installer
- `Menu.ps1` is now a real file in the repo instead of a here-string generated by the installer; the menu loops until quit
- Downloads go to a temp file and are moved into place on success, so failed downloads can't leave half-written scripts
- Removed the ICMP (`Test-Connection 8.8.8.8`) pre-flight check that failed on networks blocking ping; download errors are handled directly instead

### Fixed
- Crash when Windows Terminal `settings.json` lacked a `schemes` array or `profiles.defaults` object (`Add-Member` is now used for missing properties)
- Inconsistent `exit` / `return` usage in guard clauses

### Changed (functions)
- `space_to_dots`: now files-only, skips names without spaces (avoids rename-to-same-name errors), and shows a preview with confirmation like `mass_rename`

### Added
- `terminal_schemes.json` — all 8 Windows Terminal color schemes as data; the installer loops over the file and only writes `settings.json` when a scheme was actually added
- `-Uninstall` switch for clean removal
- `-SkipTerminal` switch
- Local-clone detection: running `Setup.ps1` from a cloned repo installs from local files (useful for testing changes before pushing)
- `CHANGELOG.md`

## [1.1.0] and earlier

Initial versions — single-script installer with hardcoded function list.
